1. Database Tables Related to Universities, Programs, Countries, and Fees

Table Purpose Key Fields
universities University master data id, type, attributes (JSONB with name, country, state, description)

3. Existing APIs for University & Program Data

Endpoint Method What it Returns
GET /universities/{school_id} GET Single university with attributes, relationships
GET /api/programs/{program_id} GET Single program full details
GET /api/program-details GET Paginated list with filters — supports university_name, program_name, country, min_fees, max_fees
GET /scholarships/{school_id} GET Scholarships for a specific university
💡 Best API for comparison: /api/program-details — already supports filtering and returns university info embedded in each program.

4. Tuition Storage: Per University or Per Program?

Answer: Tuition is stored PER PROGRAM, not per university.

  • Location: program_details.attributes["tuition"]
  • This means the same university may have different tuition for different programs
  • For comparison, you'd need to either:
    1. Compare specific programs (e.g., "MBA at University A vs MBA at University B")
    2. Calculate an average/range per university by aggregating programs

5. Performance Concerns for Fetching Multiple Universities

Concern Current State Recommendation
Query Size /api/program-details already supports pagination (default 50, max 200 per page) ✅ Safe
JSONB Filtering Uses PostgreSQL JSONB operators which are indexed ✅ Optimized
Multiple Universities Current API filters by university_name (one at a time) ⚠️ Need new endpoint for multi-university compare
No Batch University Fetch No API to fetch 2-4 universities simultaneously 🔧 Would benefit from new compare endpoint

Recommendation for Compare Feature

Create a new endpoint like:

GET /api/compare-universities?ids=123,456,789

This would:

  1. Accept multiple school_id values
  2. Fetch programs for each in a single query
  3. Aggregate tuition ranges, program counts, etc.
  4. Return comparison-ready data
