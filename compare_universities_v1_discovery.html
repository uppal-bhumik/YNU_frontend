3 Existing APIs We Can Reuse

Available Endpoints

Endpoint Returns Reusable for Compare?
GET /universities/{school_id} Single university with attributes, relationships ⚠️ Limited — one at a time only
GET /api/programs/{program_id} Single program details ❌ No — too granular
GET /api/program-details Paginated programs with embedded school data ✅ Best Candidate — has filters + combined data
GET /scholarships/{school_id} Scholarships for one university ✅ Yes — can call per university

Filters Supported by /api/program-details

Filter Parameter Type Description
university_name String Partial match on school["name"]
program_name String Partial match on attributes["name"]
country String Partial match on school["country"]
min_fees Integer Minimum tuition filter
max_fees Integer Maximum tuition filter
page Integer Pagination (default: 1)
page_size Integer Results per page (default: 50, max: 200)

Can Current APIs Support Multi-University Selection?

⚠️ Answer: NO — Not without modification

Current limitations:
  • university_name filter only accepts ONE name (partial match)
  • No school_ids parameter to fetch multiple universities at once
  • No aggregation logic (min/max tuition, program count, etc.)
  • Would require N+1 API calls to compare N universities
